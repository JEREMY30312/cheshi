## Contract Assumptions

- `normalizeEntries(rawEntries)` returns newly allocated normalized entries and does not mutate `rawEntries`.
- Supported statuses normalize as `todo|unread -> unread`, `reading|in_progress -> reading`, and `done|completed -> completed`.
- A normalized entry contains `id`, `title`, `status`, and `priority`; allowed priorities are `normal` and `high`.
- Validation failures expose one fixed code: `MISSING_ID`, `DUPLICATE_ID`, `MISSING_TITLE`, `INVALID_STATUS`, or `INVALID_PRIORITY`.
- Output ordering follows the input ordering, so repeated calls with equal input are deterministic.

## Limitations and Risks

- This module has no CLI integration; INT-001 owns command-level non-zero exit behavior.
- Final summary wording and default-branch acceptance remain outside MOD-001.
- GitHub remote branch verification was not independently established by the Reviewer after a DNS resolution failure; push status remains unknown until the implementer pushes and verifies it.
